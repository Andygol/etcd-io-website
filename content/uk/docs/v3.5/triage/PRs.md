title: Управління PR
---

## Мета {#purpose}

Прискорити управління PR.

PR для `etcd` місяться у <https://github.com/etcd-io/etcd/pulls>. PR може мати різні мітки, етапи, рецензентів тощо. Детальний список міток можна знайти на <https://github.com/kubernetes/kubernetes/labels>

Нижче наведено кілька прикладів пошуку PR для зручності:

* [Відкриті PR для етапу etcd-v3.4](https://github.com/etcd-io/etcd/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aopen+milestone%3Aetcd-v3.4)
* [PR, що розслідуються](https://github.com/etcd-io/etcd/labels/Investigating)

## Обсяг дії {#scope}

Ці рекомендації служать основним документом для управління PR в `etcd`. Кожен може допомогти в управлінні PR, але робота та обовʼязки, описані в цьому документі, створені з урахуванням підтримувачів та активних учасників `etcd`.

## Обробка неактивних PR {#handle-inactive-prs}

Підштовхуйте власника PR, якщо коментарі не були враховані протягом 15 днів. Якщо власник PR не відповідає протягом 90 днів, оновіть PR новим комітом, якщо це можливо. Якщо ні, неактивний PR слід закрити через 180 днів.

## Підштовхування рецензента, якщо потрібно {#poke-reviewer-if-needed}

Рецензенти реагують своєчасно, але враховуючи, що всі зайняті, дайте їм трохи часу після запиту на рецензію, якщо швидка відповідь не надана. Якщо відповідь не надана протягом 10 днів, не соромтеся звʼязатися з ними, додавши коментар у PR або надіславши електронний лист чи повідомлення у Slack.

## Перевірка важливих міток {#verify-important-labels}

Переконайтеся, що до PR додані відповідні рецензенти. Також переконайтеся, що визначено етап. Якщо будь-яка з цих або інших важливих міток відсутня, додайте їх. Якщо не можна визначити правильну мітку, залиште коментар для підтримувачів, щоб вони зробили це за потреби.
